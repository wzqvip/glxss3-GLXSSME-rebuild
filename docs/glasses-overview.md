# 眼镜现状调研 / Glasses situation

> 面向目标：**不再依赖已停更的原厂 App，自己做一个更好用的手机端 App**；
> 同时判断这颗芯片在不写固件的前提下还能做什么。

## 1. 产品与厂商

| 项 | 内容 |
|---|---|
| 产品 | LLVision（亮亮视野）GLXSS3 / G25 AR 眼镜 |
| 厂商现状 | 已停止支持（社区反馈公司倒闭/停运） |
| 原厂 App | `com.llvision.glxss3.camera` v2.3.7（最后一次构建约 2016-2017 年代） |
| 社区 | 有人用现成工具做过"二合一"版本（本仓库样本），但工具需付费 |

## 2. 硬件

```
SoC      Intel Movidius Myriad 2 (MA2450)   ← 与 Intel NCS1 神经棒同款
显示     640 × 400（RGBA8888 帧），亮度/开关/旋转/显示模式可 USB 控制
摄像头   UVC（USB Video Class），由 Myriad 固件透传
输入     HID（按键/触摸/传感器）
存储/固件 G25_MainFW_1.9.1.img（MA2x 容器：DDR init + main.elf）
USB      正常 0x2E09:0x0030（复合设备）；boot 0x03E7:0x2150（NCS1 引导）
```

## 3. 软件（原厂 App）做了什么

- `LLVisionPlatformService`：USB 连接管理、设备状态、固件升级入口；
- `UVCService`：摄像头预览/拍照（libuvc）；
- `LCDService`：投屏（镜像/浮层/logo）、亮度、开关、旋转、显示模式；
- `SensorService` / `KeyEventService` / `LightService`：传感器、按键、指示灯（HID/GPIO）；
- `appstore`：应用商店/账户/云（已失效，**不依赖**）。

## 4. 能力与限制

### 能做的
- 把手机任意画面（MediaProjection）以 **640×400 RGBA** 投到眼镜；
- 投"浮层"（只投一个 View）；
- 控制亮度/开关/旋转/显示模式；
- 通过 UVC 取眼镜摄像头画面（预览/拍照）；
- 读取 HID 输入（按键等）。

### 原厂 App 的限制（也是新 App 的机会）
- 只支持 640×400 一种分辨率、单一投屏模式，无缩放/裁剪选项；
- 没有断电/断开自动重连、没有重试与超时提示；
- 没有帧率/带宽控制，画面卡顿无处理；
- 没有"只投某 App"、没有横竖屏/镜像翻转、没有亮度快捷调节；
- 依赖已失效的 appstore/账户体系；
- 代码质量差（jadx 可见大量复制粘贴、异常吞掉）。

## 5. 新 App 的定位

**一个干净的、开源的非商业替代品**：

- 直接走 USB（Android USB Host API），不依赖任何私有 SDK；
- 复用本仓库逆向出的协议（16B 头 + RGBA 帧）；
- 提供更好的投屏体验（见 [app-replacement.md](app-replacement.md)）；
- 可选保留 UVC 摄像头功能。

## 6. 不写固件，能用上神经棒吗？

**能，但要取舍。** 详见 [soc-myriad2.md](soc-myriad2.md) 与 README 的说明，结论：

| 方式 | 是否可行 | 代价 |
|---|---|---|
| 保留厂商固件（现状） | 只能当"显示器 + 摄像头"，**无法跑自定义 NN** | 无风险 |
| 启动 Intel 官方 NCS1 固件（`ma2x8x.mvcmd`） | **可以**，设备变成标准 NCS1，可用 NCSDK/OpenVINO 跑推理 | **失去显示与摄像头**（该固件不驱动厂商外设）；需能拿到固件；有兼容/变砖风险（可回刷） |
| 自己写 MVCMD | 可以，但需要 MDK | 工具链难获取 |
| 手机/PC 侧跑推理 | 最稳 | 浪费 Myriad 2 的算力 |

> 结论：**"神经棒"能力与"显示/摄像头"能力在现有固件下是互斥的**（固件不同）。
> 如果目标是"更好用的投屏 App"，就走保留厂商固件的路线；如果目标是"拿它当 NCS 跑模型"，
> 就要接受它变成一块普通的神经棒、显示屏和摄像头不可用。
